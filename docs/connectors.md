# 接上 AI 用戶端（連接器）

App 在手機上提供 MCP：`http://127.0.0.1:47823/mcp`（Streamable HTTP，`Authorization: Bearer <token>`）。
token 在「設定 → MCP 連線」，顯示 / 複製前要指紋或螢幕鎖確認；可以隨時換新 token（舊的立即失效）。

```json
{"mcpServers":{"line":{"type":"http","url":"http://127.0.0.1:47823/mcp","headers":{"Authorization":"Bearer <token>"}}}}
```

## 由連接器代聊（不需要 App 內 API key）

總控台 → 「誰來代聊？」選 **由連接器代聊**。外部 AI 用 `send_message` 回覆，App 端照樣把關：

1. 「AI 代聊總開關」要開
2. 聊天要同時在 **MCP 白名單**（聊天列表勾選）和 **AI 代聊名單**（聊天 → AI 設定）
3. 模式：`僅建議回覆` → 一律進確認佇列；`AI 代聊` + 「發送前確認」開（預設）→ 進確認佇列；確認關掉才會延遲後直接送
4. 間隔、每小時 / 每天上限、全部聊天每日上限、活躍時段、緊急停止全部生效
5. 每次呼叫都寫入稽核紀錄；送出類工具另有每分鐘 10 次的速率限制

`send_message` 回傳 `status: "pending"` 代表在等你按「送出」；之後可用 `get_outbox_item` 查狀態。
`list_allowed_chats` 會告訴 AI 每個聊天能不能送、會不會先進確認佇列。

## 誰連得到 127.0.0.1？

MCP 只綁手機本機 loopback，所以只有**在同一支手機上**執行的用戶端連得到（例如 Termux 裡的 CLI 用戶端、手機上的 MCP 相容 App）。
雲端 AI（網頁版 / 手機 App 的雲端連接器）跑在對方伺服器上，**連不到你手機的 127.0.0.1**。

## 雲端連接器排程輪詢反詐警示（需要通道）

`scan_scam_alerts(since, chat_id?)` 設計給排程輪詢：每次把回傳的 `next_since` 當下一次的 `since`。

- **本機**（同一支手機上的用戶端）：直接呼叫，最安全
- **雲端**：必須自己架通道（例如 Tailscale Funnel、Cloudflare Tunnel）把手機的 `127.0.0.1:47823` 轉出去。注意：
  - App 會拒絕非 loopback 的 `Host` 標頭與任何帶 `Origin` 的請求，通道要以 `127.0.0.1:47823` 轉送並改寫 Host
  - 等於把你的 LINE 讀取權限放上網路：務必用通道本身的存取控制（身分驗證 / IP 限制），token 定期更換
  - 建議只開放唯讀需求，並把要給雲端的聊天控制在最少
  - App 不內建任何對外通道，這一步風險由你自己評估

## 反詐即時提醒

和連接器無關，App 本機規則就能運作：聊天 → AI 設定 → 「反詐即時提醒」（每群預設關）。開啟後偵測到換群 / 詐騙話術會立刻引用那則訊息回一句提醒，可 @ 管理員（最多 3 位），範本可改：

```
⚠️ 這則疑似「{category}」詐騙：{tip}。@{admins} 請確認處理。
```

不會引用詐騙內容；同一人同類型 30 分鐘冷卻、每群每天最多 10 則、緊急停止一樣擋得住。
